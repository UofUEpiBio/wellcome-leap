What this tool is

This page was created by our team for the Wellcome Leap AMPLIFY proposal. It is a functional prototype: every number it shows is produced by a model we actually fitted, not by a mock-up. It exists to demonstrate, end to end, the three pieces the full project brings together.

  1. 1

    The mechanistic model

    A stochastic agent-based SEIR simulation of two antibiotic-resistant organisms. Each simulated individual carries a feature that shifts their per-contact transmission probability, so the simulation produces a realized number of secondary infections for every infected agent.

  2. 2

    The machine-learning component

    A count-regression neural network trained on those simulated individuals, using multimodal input with deliberate information loss: during training, each row randomly keeps both inputs, the individual feature alone, or the organism scenario alone. The model therefore stays usable when a modality is missing, instead of failing or silently imputing it.

  3. 3

    The application

    This interface. It carries the fitted weights directly and evaluates them locally, which is how the delivered tool is intended to feel: a practitioner supplies whatever they have, and gets an interpretable estimate back immediately.

How to read the flag. The estimate is an expected count of secondary infections from this one individual. Above 1.1 we flag outbreak potential: this individual is expected to more than replace themselves. Below 0.9 we flag self-limiting. In between we flag borderline rather than pretending the model can separate the two — the prototype's test error is of the same order as the threshold itself.

What the full version will accept

The prototype exposes two attributes because the simulation that trained it has two. The production tool is designed around the same missing-modality machinery, applied to real inputs: users will be able to upload or connect clinical data (cultures, treatment and antibiotic exposure, comorbidities, admissions), sociodemographic data (household structure, occupation, contact patterns, sanitation and environmental context), and omics data (isolate genomes, plasmid and resistance-gene content, microbiome composition) — and, in principle, further modalities such as environmental surveillance or facility movement records.

Crucially, none of these is required. The training strategy demonstrated here — randomly withholding modalities so the network learns to condition on what is actually present — is what lets a user estimate with whatever they happen to have, rather than being locked out for lacking a data type.

What we plan to release

A library

The simulation, training, and prediction pipeline as an installable package, so that other groups can retrain on their own populations, script batch estimates, and audit every step.

A graphical interface

A tool in the spirit of this page, for users who need an estimate rather than an API — with data upload, cohort-level views, and exportable results.

Both will be released as open source software.

Honest limitations

  • The training data are simulated. This prototype demonstrates that the machinery works; it does not yet say anything about real organisms or real patients.
  • The two scenarios are very unbalanced in the training data, because a lower-transmission organism produces far fewer infected agents. With the individual feature alone, the model leans toward the higher-transmission regime it saw most.
  • The estimate is an expected count. Realized secondary infections are highly dispersed, so a single individual's outcome will often differ substantially from their expectation.
