How to read the flag. The estimate is an expected count of secondary infections from this one individual. Above 1.1 we flag outbreak potential: this individual is expected to more than replace themselves. Below 0.9 we flag self-limiting. In between we flag borderline rather than pretending the model can separate the two — realized secondary infections are far more variable than the width of that band, so a near-one estimate is a question, not an answer.

What this tool is

This page was created by our team for the Wellcome Leap AMPLIFY proposal. It is a functional prototype: every number it shows comes from a model we actually fitted, evaluated in your browser, not from a mock-up. A user supplies whatever they have — colonisation and exposure measurements, an organism identification, or only one of the two — and gets an interpretable estimate back immediately.

The inputs are labelled with the clinical, microbiological, and omics quantities the delivered tool is designed around. Underneath, the prototype's simulation supplies a single standardized transmissibility feature, so the page maps the profile items onto that one feature with the illustrative weights shown under How it works. The machinery — including the ability to estimate with a whole modality missing — is real; the numerical weight of any individual clinical item is not yet.

The three pieces this prototype joins

  1. 1

    The mechanistic model

    A stochastic agent-based SEIR simulation of two antibiotic-resistant organisms. Each simulated individual carries a feature that shifts their per-contact transmission probability, so the simulation produces a realized number of secondary infections for every infected agent.

  2. 2

    The machine-learning component

    A count-regression neural network trained on those simulated individuals, using multimodal input with deliberate information loss: during training, each row randomly keeps both inputs, the individual feature alone, or the organism alone. The model therefore stays usable when a modality is missing, instead of failing or silently imputing it. The two organisms are weighted equally during training, so an estimate made from one modality genuinely averages over the other.

  3. 3

    The application

    The estimator on the first tab. It carries the fitted weights directly and evaluates them locally, which is how the delivered tool is intended to feel: a practitioner supplies whatever they have, and gets an interpretable estimate back immediately.

How the inputs map onto the model

The fitted surrogate takes exactly two things: one standardized individual feature and the organism label. The simulation behind it generates that feature directly, so it has no clinical units of its own. To keep the estimator recognisable, this page presents it as a transmissibility index assembled from familiar carriage, exposure, and contact measurements:

InputModalityContribution to the index

The contributions are illustrative: they encode the direction and rough ordering that the AMR literature supports, not weights estimated from patient data. They live in app/site.json and can be edited without touching any code. The index is capped at ±3, the range the training data covers. Everything downstream of the index — the network, the missing-modality behaviour, the estimate — is the fitted model.

The organism choice is a relabelling of the same kind. The simulation calibrates a lower- and a higher-transmission organism, near population reproduction numbers of 1.5 and 3.0; the page presents them as an ESBL-producing E. coli and a carbapenem-resistant K. pneumoniae so the contrast is concrete. The estimates are not organism-specific evidence about either species.

What the full version will accept

The prototype exposes two modalities because the simulation that trained it has two. The production tool is designed around the same missing-modality machinery, applied to real inputs: users will be able to upload or connect clinical data (cultures, treatment and antibiotic exposure, comorbidities, admissions), sociodemographic data (household structure, occupation, contact patterns, sanitation and environmental context), and omics data (isolate genomes, plasmid and resistance-gene content, microbiome composition) — and, in principle, further modalities such as environmental surveillance or facility movement records.

Crucially, none of these is required. The training strategy demonstrated here — randomly withholding modalities so the network learns to condition on what is actually present — is what lets a user estimate with whatever they happen to have, rather than being locked out for lacking a data type.
